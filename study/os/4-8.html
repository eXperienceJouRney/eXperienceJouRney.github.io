4.8 操作系统的并发机制实例

前几节讲的是互斥与同步的原理，这一节看操作系统真正提供出来的接口：以 Linux 为例，信号量如何创建、控制、施加操作，以及共享内存怎样释放。看完这一节，应当能把「信号灯就是一个整型变量加一个等待队列」这一概念，与 semget、semctl、semop 这几个系统调用对应起来。

1. Linux 信号量及其使用方法

Linux 信号量函数是在通用的信号量数组上进行操作的，而不是在单个信号量上操作——这是它与课堂上「一个信号灯就是一个整型变量」最直观的区别。一组相关的信号量可以放在同一个数组里一次创建、统一管理，每个元素相当于一个独立的信号灯。与信号量有关的系统调用主要有三个：semget、semop 和 semctl，分别对应创建、操作和控制。

（1）信号量的创建

int semget(key_t key,
           int num_sems,
           int sem_flags)

semget 的功能是创建一个新的信号量，或者获得一个已存在的信号量。三个参数的含义是：

  • key：一个用来允许多个进程访问同一个信号量的整数值。只要各进程用相同的 key 值调用 semget，它们就能定位到同一个信号量，这是互不相识的进程之间「约定」同一个同步机构的办法；
  • num_sems：所需要的信号量数目。semget 创建的是一个信号量数组，数组元素的个数即为 num_sems，所以取 1 就得到一个信号量；
  • sem_flags：一个标记集合，与 open 函数的标记十分类似。它的低九位是信号量的权限，作用与文件权限类似；这些标记还可以与 IPC_CREAT 进行或操作，表示「不存在就创建」。一般写作 IPC_CREAT | 0666。

（2）信号量的控制

int semctl(int sem_id,
           int sem_num,
           int command, ...)

semctl 用来对信号量实施控制，参数含义如下：

  • sem_id：由 semget 所获得的信号量标识符；
  • sem_num：信号量数组元素的下标，用来指定对第几个信号量进行控制；
  • command：要执行的动作，有多个不同的 command 值可以用于 semctl。常用的两个是 SETVAL——为信号量赋初值，其值通过第四个参数指定；以及 IPC_RMID——当信号量不再需要时，用于删除一个信号量标识。

（3）信号量的操作

真正对信号量做「加一减一」这类动作的是 semop，其原型为：

int semop(int sem_id,
          struct sembuf *sem_ops,
          size_t num_sem_ops)

它一次可以对数组中的若干个信号量施加一组操作，参数 sem_ops 指向描述这些操作的结构体数组，num_sem_ops 说明操作的个数。所谓一次完成一组操作，正是「原语」这一要求在系统调用层面的体现：一个进程对多个信号量的动作要么全部生效，要么一个也不做，不会被别的进程从中间插进来。

2. 共享内存的释放

共享内存是进程通信中效率最高的一种方式：同一块物理内存被映射到多个进程的地址空间里，进程读写它就像读写自己的内存，数据不需要在进程之间来回复制。共享内存的句柄由 shmget 调用返回，当它不再需要时，用 shmctl 释放：

系统调用格式：int shmctl(shmid, cmd, buf);

其中：

  • shmid：共享内存句柄，即 shmget 调用的返回值；
  • cmd：操作命令，释放时取 IPC_RMID；
  • buf：操作参数，类型为 struct shmid_ds *buf。

所以释放一块共享内存的典型写法是：

shmctl(shmid, IPC_RMID, NULL);

把两件事对照起来看：信号量用 semctl(…, IPC_RMID, …) 删除，共享内存用 shmctl(…, IPC_RMID, …) 删除——Sys V 这一族 IPC 资源都用「xxxctl + IPC_RMID」来回收，这是它们接口风格统一的地方。

本节小结

  • Linux 的信号量作用在信号量数组上，用 key 让多个进程访问同一组信号量；
  • 三个系统调用分工明确：semget 创建或获取信号量（参数为 key、信号量个数、标记，标记常用 IPC_CREAT | 0666），semctl 控制信号量（常用命令 SETVAL 赋初值、IPC_RMID 删除），semop 对信号量施加操作；
  • 共享内存由 shmget 返回句柄，用 shmctl(shmid, IPC_RMID, NULL) 释放；
  • 信号量与共享内存都属于 Sys V 一族的 IPC 资源，创建—控制—操作（使用）—回收的接口风格是一致的。
