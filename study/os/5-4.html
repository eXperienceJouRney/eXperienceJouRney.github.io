操作系统原理 · 第 5 章 资源分配与调度

5.4 死锁的预防

上一节归纳出产生死锁的四个必要条件：互斥、不可抢占、占有并等待、环路条件。解决死锁问题最直接的思路就是「拆掉其中任意一条」。这一节逐条讨论破坏这四个条件的办法，看看每条办法需要付出什么代价、在什么场合行得通，重点是有序资源分配法——它既能动态申请，又能从原理上证明不会死锁。

1. 总思路：破坏死锁产生的四个条件

死锁的四个必要条件是「同时成立才死锁」，所以只要能破坏其中任何一条，死锁就不可能发生。这种思路称为死锁的预防：它是在资源分配之前就把规则定死，使系统在结构上不具备死锁的可能。四条路各有各的代价，下面一一来看。

2. 破坏第一个条件：互斥

互斥条件说的是「资源一次只能给一个进程使用」。要破坏它，就得使资源可以同时访问，而不是互斥使用。比如内存、磁盘就可以用这种办法管理：多个进程可以同时读同一份数据，只要不写，彼此互不影响。

但这条路的局限也很明显：许多资源往往是不能同时访问的，比如打印机、光驱——两个进程同时往一台打印机上送数据，输出就是一锅粥。所以这种做法在许多场合行不通。课件提到的一个补充手段是虚拟设备：用共享设备模拟独占设备，让每个进程都觉得自己独占了一台设备（实际上排队使用），从而把「物理上互斥」变成「逻辑上可同时申请」。不过虚拟设备只是在用户的观感上化解了互斥，真正访问物理设备的那一段仍然是串行的。

3. 破坏第二个条件：不可抢占

不可抢占条件说的是「资源一旦被占有，就不能被强行夺走」。要破坏它，就采用可抢占式的调度方法：发现某个进程需要的资源在别人手里，就把资源抢占过来给它。

代价是显而易见的：被抢占的进程正在做的事情必须能够被打断并重新开始，因此这条办法只适用于资源状态可以保存和恢复的情况。处理器就是最典型的例子——把当前进程的现场保存起来，就可以把处理机交给别的进程，之后再恢复现场继续执行。相比之下，打印机打印到一半是无法「保存状态」的，抢过来也没有意义；共享数据被修改到一半同样不能抢占。

4. 破坏第三个条件：占有并等待

这一条有两个办法，本质上都是让进程在等待新资源时不再抱着已有的资源不放。

第一个办法是申请失败就主动释放：当进程在申请资源未获准许的情况下，主动释放掉已经占有的资源，以后再一起向系统提出申请；或者在申请资源之前就释放掉已经占有的资源。这个办法听起来合理，但课件明确指出它几乎不可能实施——进程干到一半把已经拿到的资源全部退回去，之前做的工作往往就白费了。

第二个办法是静态分配策略：进程需要的资源只能一次申请，在没有获得全部资源前不能投入运行；进程运行完，一次释放所有资源。这正好与 5.1 节讲的「作业一级采用静态分配」对应起来——一次性给全，运行期间不再申请，自然也就不存在「占有并等待」。

静态分配确实能避免死锁，但缺点也很突出：

  • 一个用户（进程）在程序运行之前很难提出将要使用的全部资源；
  • 用户作业需要的某些资源可能在后期才使用，提前申请意味着提前占用；
  • 资源浪费太大：有些资源在进程运行过程中可能只有很少的时间会用到，有的甚至根本不会用到，例如一个出错处理的分支语句——正常情况下它永远不执行，可它需要的资源却要一直被占着。

5. 破坏第四个条件：环路条件

前三条路要么行不通，要么代价太大，于是主要的注意力落在第四条上：资源仍然动态分配，但通过控制分配来避免死锁。课件给出两条路子——有序资源分配法与银行家算法（资源分配拒绝策略），后者是下一节的主题。

（1）有序资源分配法的规则

有序资源分配法的做法是：系统中所有资源都给定一个唯一的编号，所有分配请求必须以上升的次序进行。当遵守上升次序的规则时，若资源可用，则予以分配；否则，请求者等待。也就是说，进程不能想申请哪个就申请哪个，必须先申请小编号的资源，再申请大编号的资源；一旦申请了编号较大的资源，就再也不能回头申请编号较小的资源。

举个最简单的例子：进程 PA 和 PB 都要使用资源 R1、R2，规定 R1 编号为 1、R2 编号为 2。那么 PA 的申请次序应当是 R1、R2，PB 的申请次序也应当是 R1、R2。回想上一节的序列 4——p1 按 R1→R2、p2 按 R2→R1 申请，结果死锁；在有序分配法下这种「次序相反」的情形被规则本身禁止了，死锁也就无从发生。

（2）为什么不可能产生死锁

设进程集合 P = { p1, p2, …, pn }，资源集合 R = { r1, r2, …, rm }，任一进程申请资源必须按照资源编号（1, 2, …, m）升序的顺序申请。下面用反证法证明不可能产生死锁。

假设有序分配法会产生死锁。则在死锁时刻，若进程 P1 处于等待资源 rk1 的状态，那么 rk1 必为另一进程（假定是 P2）所占用，所以一定在之前某个时刻，进程 P2 占有资源 rk1 而又处于永远等待资源 rk2 的状态。如此推下去，系统只有有限个进程，一定存在进程 Pn 永远等待资源 rkn，而 rkn 必为前面某个进程 Pi（i < n）占用。

按照按序分配的规则，当 P2 占用了 rk1 之后再申请 rk2，必有 k1 < k2；依此类推，可得

k1 < k2 < … < ki < … < kn

但进程 Pi 已经占有了 rkn，却还要申请 rki，按同一规则又必须有 kn < ki。一串严格递增的编号里不可能出现「最后一个小于前面的某一个」，这就产生了矛盾。所以按序分配策略可以防止死锁。

还有一个更直观的说明：因为所有进程申请资源必须按资源编号升序进行，那么在任意时刻，总有一个进程占有较高序号的资源，而它继续申请的其他资源必然是空闲的——否则就意味着有另一个进程「先占了高序号资源、再回头申请低序号资源」，这与规则矛盾——所以该进程总可以向前推进。即系统中总有进程可以运行，因此不会死锁。

（3）优缺点

  • 优点：不需要预先说明各类资源的最大需求量，可以动态申请，只需要按序申请即可；
  • 缺点：进程实际使用资源的顺序不一定与资源的编号相一致，为了遵守次序，可能不得不提前申请、提前占用某个资源，从而降低利用率。

课件在这里留了一个讨论题：这种方法破坏了产生死锁条件中的哪一条？答案是环路条件（循环等待）——所有进程都按同一个方向申请资源，就不可能形成「你等我、我等你」的环路。

本节小结

  • 死锁预防的总思路是破坏四个必要条件中的任意一条：互斥、不可抢占、占有并等待、环路条件；
  • 破坏互斥：让资源可同时访问（如内存、磁盘的读），或用虚拟设备模拟独占设备；但打印机这类资源物理上无法同时访问，多数场合行不通；
  • 破坏不可抢占：采用可抢占式调度，只适用于状态可以保存和恢复的资源，处理器是典型例子；
  • 破坏占有并等待：申请失败即主动释放已有资源（几乎不可能实施），或采用静态分配策略（作业一次申请全部资源、运行完一次释放）；静态分配的缺点是事先难以说明全部需求、后期才用的资源被提前占用、资源浪费大；
  • 破坏环路条件：资源动态分配但控制分配方式，代表方法是有序资源分配法与银行家算法；
  • 有序资源分配法：给所有资源唯一编号，申请必须按编号升序进行。可用反证法证明它不会死锁（否则会推出 k1<k2<…<kn 与 kn<ki 的矛盾）；优点是不需要预先说明最大需求量、可动态申请，缺点是实际使用顺序未必与编号一致。
