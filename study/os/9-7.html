操作系统原理 · 第 9 章 文件系统

9.7 文件操作与文件备份

文件系统建立起来之后，用户真正打交道的是「文件操作」：建立、读写、改名、删除、共享，每一项都是通过一条命令请求操作系统代为实现的。而文件一旦被误删或介质失效，数据就没了，所以文件系统还必须提供备份与恢复的机构。这一节先看有哪些常用的文件操作命令，再讲其中最容易被忽视的打开与关闭两个操作，最后讲文件备份的必要性、两种基本的转储方法以及备份技术的发展。

1. 常用的文件操作命令

用户对文件提出的各种要求，最终都要由操作系统去执行，这中间的接口就是一组文件操作命令。课件把它们整理成一张对照表，按作用对象大致可以分成五类：对文件本身进行管理的（create、delete、rename、file attribute、file date），对文件内容进行读写的（write、read），打开与关闭文件的（open、close），读取目录与磁盘信息的（directory read、disk space），以及建立和拆除共享关系的（link、unlink）。

课件第 89–90 张的表格：常用的文件操作命令
命令 说明
create创建一个新文件
delete从系统目录中撤消一个文件
rename在系统目录中改变文件的名字
file attribute设置文件属性
open打开文件
close关闭文件
write写到一个文件（或设备）上
read从一个文件（或设备）读入数据信息
directory read读目录信息
disk space确定一个设备上可用磁盘区域的大小
link建立链接
unlink删除链接
file date改变文件的时间

这张表里有几处值得在讲课时点出来。一是 read 与 write 的对象并不限于磁盘上的文件——课件特意在括号里注明「或设备」，这与 UNIX 把外部设备统一当作文件来对待的思想是一致的，9.8 节讲 UNIX 文件系统的实现时会看到它的落地方式。二是 link 与 unlink 改动的不是文件内容，而是文件之间的链接关系，它们正对应 9.5 节讲过的链接技术：在目录表目之间建立指向关系，使一个文件可以被多个目录项共同使用；不再共享时就删掉这条链接。三是 file attribute 与 file date 修改的是文件的属性信息，其中包含 9.6 节讲过的用户存取权限（那里就以 CHANGE 表示改变文件属性）；而 disk space 问的是「这个设备上还有多大空闲区域可用」，与 9.4 节的文件存储空间管理直接相关。

注记：课件第 90 张把读目录信息的那条命令写作 dirctory read，是 directory read 的笔误。

2. 打开与关闭文件

在全部命令里，open 和 close 最容易被当成可有可无的礼节性动作，实际上它们决定了文件能否被高效地反复使用。要看清这一点，先看这两个操作究竟做了什么。

（1）打开文件

所谓打开文件，就是把该文件的有关目录表目复制到主存中约定的区域，建立文件控制块（FCB，File Control Block），从而建立用户和这个文件的联系。关键词是「复制到主存」：文件目录平时存放在磁盘等辅存上（见 9.5 节），如果每次读写都要到辅存上去查目录、核对权限、定位物理块号，开销大得无法接受。打开操作相当于把这份目录信息一次性搬进主存并组织成文件控制块，此后对该文件的所有 read、write 都直接使用主存中的 FCB，不必再来回访问目录。

（2）关闭文件

所谓关闭文件，就是用户宣布这个文件当前不再使用，系统将其在主存中的文件控制块删去，因而也就切断了用户同这个文件的联系。关闭之后若还要读写，必须重新打开。可见 open 与 close 是一对配对使用的操作：打开是「把目录信息取进来」，关闭是「把主存里的这份信息撤掉」，一进一出，主存资源才能循环使用。

（3）活动文件表

由此引出一个术语：若一个文件的目录表目被复制到主存，则称它为已打开的（或活动的）文件。这些目录表目在主存中统一存放，形成一张活动文件表。已打开的文件可以多次使用，这正是先 open、再反复 read/write 的价值所在——一次打开、多次使用，比每次操作都重新查目录划算得多。反过来说，活动文件表占用主存，所以同时打开的文件数通常也受到系统的限制。下一节 9.8 讲 UNIX 文件系统的主要结构及实现时，这些结构会落到具体的名字上：主存中的活动 i 节点与系统打开文件表，对照着看，open/close 的完整过程就清楚了。

3. 文件备份的必要性

文件系统把数据长期保存下来，但保存本身并不可靠。为了能在软、硬件失效的意外情况下恢复文件，保证文件的完整性、数据的连续可利用性，文件系统提供适当的机构，以便复制备份。这就是文件备份要解决的问题。

所谓「软、硬件失效的意外情况」，在课堂上可以分两头讲。软件一侧：操作系统或文件系统的缺陷、掉电时写到一半的目录与数据、用户的误删除和误覆盖、恶意程序对文件的破坏。硬件一侧：磁盘出现坏道、磁头或控制器故障、整台存储设备报废，以及火灾、水淹这类伤及机房的灾难。这些事故的共同特点是发生前无法预知、发生后原数据已经不可读，唯一的出路是事先另存一份副本。

备份要达到的目标也由原文的两个说法界定：一是文件的完整性，恢复回来的内容应当完整、没有残缺；二是数据的连续可利用性，恢复之后数据能接着用、业务能接着跑，而不仅仅是「还剩一些碎片」。这里要和 9.6 节的文件安全区分开：文件安全解决的是「哪些用户可以在什么权限内使用文件」，防的是未授权的存取；文件备份解决的是「数据损坏或丢失之后还能不能恢复」，防的是数据本身的灭失。两者保护的不是同一件事，所以一个都不能少。

4. 两种备份方法及其发展

（1）周期性转储（全量转储）

第一种方法按固定的时间周期把存储器中所有文件的内容转存到某种介质上，通常是磁带或磁盘。在系统失效时，使用这些转存磁盘或磁带，将所有文件重新建立并恢复到最后一次转存时的状态。

它的好处是转储下来的就是一份完整副本，恢复过程简单直接——把这批介质上的文件重新写回即可，不必挑拣也不必拼接。代价同样明显：每一次都要把全部文件（包括长期没有改动的部分）重新写一遍，耗时长、占用介质多，转储期间系统负担也重；而受时间限制，转储周期不可能太短，两次转储之间发生的改动一旦丢失就找不回来了。这一矛盾正是下一种方法出现的原因。

（2）增量性转储

增量性转储这种技术转储的只是从上次转储以后已经改变过的信息；增量转储的信息量较小，故转储可在更短的时间周期内进行。改动越少，转储越快，于是可以把周期缩得很短，两次转储之间可能丢失的数据窗口也就跟着变小。

实际系统里两种方法是配合使用的：周期性地做一次全量转储作为基准，两次全量之间按更短的周期做增量转储。这样，恢复时要先恢复最近一次全量转储，再按时序依次恢复其后的各次增量，才能回到失效前的状态。这也意味着增量的链条不能断——只要中间某一次增量介质损坏，该次之后的改动就都无法恢复了。课件原文只讲了两种方法各自的做法，这层配合关系是理解它们为什么要放在一起的关键。

（3）文件操作事务、日志文件系统与文件系统快照

课件在两种转储之外还列出了三项机制。它们与定时转储的思路不同：不是「过一段时间复制一份」，而是从变化本身入手保证文件系统的一致性。文件操作事务把若干个文件操作作为一个不可分割的单位，要么全部完成、要么全部不做，避免留下只改了一半的中间状态；日志文件系统在真正改动数据之前先把要做的改动记入日志，修改过程中若系统崩溃，可以依据日志重做或撤销，使文件系统恢复到一致状态；文件系统快照则记录文件系统在某一时刻的一致映像，生成快、代价小，常被用作备份的数据来源。

注记：课件在这里只列出了这三个名称，上面一段是按这些术语的通用含义作的解释，其实现细节已超出原文口径，讲课时点到即止即可。

（4）文件备份的发展

课件把文件备份的发展概括为两条线索。一是动态备份：备份可以在系统运行过程中进行，不必让系统停下来。停机会中断服务，而全量转储动辄要跑几个小时，很难找到这样的停机窗口；把转储放到系统运行中完成，备份与可用性之间的冲突就缓解了。二是远程备份技术：备份的副本要离开本地。如果备份介质和原数据放在同一个机房，火灾、水淹、断电、整机损毁等事故会同时毁掉两者，备份也就白做了；把副本送到异地存放，才有对付这类本地灾难的能力。

本节小结

  • 常用的文件操作命令按作用对象分为五类：文件本身的管理（create、delete、rename、file attribute、file date）、内容的读写（write、read）、打开与关闭（open、close）、目录与磁盘信息（directory read、disk space）、共享链接（link、unlink）。read 与 write 的对象可以是文件，也可以是设备。
  • 打开文件＝把该文件的目录表目复制到主存、建立文件控制块（FCB），建立用户与该文件的联系；关闭文件＝删去主存中的文件控制块，切断这一联系。已打开的文件（活动文件）的目录表目在主存中统一存放，构成活动文件表，可以被多次使用。
  • 文件备份是为了在软、硬件失效的意外情况下恢复文件，保证文件的完整性与数据的连续可利用性；它与 9.6 节的文件安全不是一回事——安全管「谁能用」，备份管「坏了能不能恢复」。
  • 周期性转储（全量转储）按固定周期把所有文件转存到磁带或磁盘，恢复简单但耗时、耗介质，两次转储之间的改动会丢失；增量性转储只转存上次转储后改变过的信息，信息量小、周期可以更短，通常与全量转储配合使用，恢复时按「最近一次全量＋其后的各次增量」依次还原。
  • 文件备份的发展有两条线索：动态备份（在系统运行中完成备份，避开停机窗口）与远程备份技术（副本异地存放，防范本地灾难）。课件另列的文件操作事务、日志文件系统与文件系统快照，则把备份推进到对文件系统变化本身的一致性管理。
