操作系统原理 · 第 4 章 进程及进程管理

4.11 小结

这一节把第 4 章「进程及进程管理」串一遍。章内的逻辑其实是一条链：为什么要引入进程 → 进程是什么、怎么描述、怎么控制 → 进程之间为什么互相制约 → 用什么机构去协调 → 这些机构怎样落在具体程序里 → 线程带来了什么变化 → Linux 上是怎样实现的。下面按这条链回顾每一环的关键结论，便于把散在各节的知识点重新组织成一张网。

1. 进程概念

进程概念的起点是程序的执行方式。程序顺序执行时具有顺序性、封闭性和可再现性；多道程序环境下程序并发执行，这三条性质都不再成立——执行过程被走走停停地打断，多个程序共享资源、互相影响，结果与时间有关。为了描述这种并发执行的活动，才引入了进程：进程是程序在一个数据集合上的一次运行过程，是系统进行资源分配和调度的基本单位。它与程序的区别在于「动」与「静」：程序是静态的指令集合，可以长期保存；进程是动态的，有创建、运行、消亡的生命周期。

进程的状态是刻画它动态性的主要工具：三个基本状态——就绪、运行、等待（阻塞），以及三者之间的变迁关系构成了进程的状态变迁图。不同操作系统类型（如批处理系统、分时系统）中，进程的状态划分与变迁图会有所不同，例如分时系统中运行态与就绪态之间的转换更频繁。进程又靠什么来描述？靠进程控制块 PCB：它记录了进程的标识、状态、现场信息以及资源清单等，是操作系统感知和控制进程的唯一依据，所以进程的组成可以写作「PCB + 程序 + 数据」。

2. 进程控制

进程的创建、撤销、等待与唤醒都由进程控制原语完成，原语的特点是执行不可分割——在执行过程中不允许被中断，否则进程状态会处于中间的不一致状态。基本的进程控制原语包括创建进程、撤销进程、进程等待（阻塞）和进程唤醒，它们的功能可以对照着记：

  • 进程创建原语：为进程分配 PCB 及所需资源，把新进程插入就绪队列；
  • 进程撤销原语：回收进程占用的资源，撤销其 PCB；
  • 进程等待原语：把当前进程由运行态变为等待态，插入相应资源的等待队列，并转调度；
  • 进程唤醒原语：把等待队列上的进程移出，置为就绪态，插入就绪队列。

可以看到，原语的执行与进程状态的变化是严格对应的：创建使新进程进入就绪态，等待使运行态转为等待态，唤醒使等待态回到就绪态，撤销使进程走向终止。

3. 进程之间的相互制约关系与同步机构

并发进程之间存在两种制约关系，它们的来源不同：互斥来自对临界资源的争用——一次只允许一个进程使用的资源叫临界资源，访问它的那段程序叫临界区，多个进程不能同时进入自己的临界区，这就是互斥；同步来自进程之间的协作——几个进程为了完成共同的任务，必须按某种先后次序推进，例如看病与化验，化验进程必须等看病进程开出化验单才能工作。

协调这两种关系的是操作系统提供的同步机构，本章讲了两类。第一类是锁：用一个锁变量 w 记录资源是否被占用，配以上锁原语（测试 w，为 0 则置 1 并进入临界区，为 1 则等待）与开锁原语（把 w 置 0，必要时唤醒等待者），等待方式有自旋与挂起两种，分别对应自旋锁和普通锁 mutex。第二类是 1965 年 Dijkstra 提出的信号灯（信号量）：它是一个二元组 (s, q)，s 是带非负初值的整型变量，代表可用资源实体的数量，q 是初态为空的等待队列；对它的两种原语操作是 P 操作（s 减 1，结果为负则挂起调用进程）和 V 操作（s 加 1，结果不大于零则唤醒等待队列上的一个进程）。信号灯的取值本身就是信息：正值表示还可使用的资源数，负值的绝对值表示等待队列中的进程数。

4. 进程互斥与同步的实现

用机构去解决实际问题，第一步总是「设信号灯并说明它的意义和初值」。互斥只需一个初值为 1 的互斥信号灯：进程在临界区前后各做一次 p(mutex) 与 v(mutex)；两个并发进程时 mutex 只取 1、0、−1 三个值，n 个进程时则可能取 1, 0, −1, …, −(n−1)。

同步问题分两类，解法已经形成了固定套路——先画进程流图分析同步关系，再设信号灯，最后写程序描述：

  • 合作进程的执行次序：同步信号灯初值为 0，由前驱进程在结束时用 V 操作「发放通行证」，后继进程在开始处用 P 操作等待，例如 pa 结束后 pb、pc 才能开始的例子；
  • 共享缓冲区的合作进程：需要两个同步信号灯，一个表示缓冲区中有无信息（初值 0），一个表示有无空位置（初值 1），cp 与 iop 就是这样配合的。

把后一类推广到多生产者、多消费者，就是本章的压轴内容生产者—消费者问题的一般解答：设 sb 表示空缓冲区数目（初值 n）、sa 表示满缓冲区数目（初值 0），两者负责同步；再设 mutex（初值 1）负责对缓冲区本身的互斥访问。生产者「生产 → p(sb) → p(mutex) → 放入 → v(mutex) → v(sa)」，消费者「p(sa) → p(mutex) → 取出 → v(mutex) → v(sb) → 消费」，两条流水正好对称。这一结论在第 5 章还会用到：把其中 P 操作的次序颠倒，就会造成死锁。

5. 线程与 Linux 的实现实例

进程虽然解决了并发问题，但它把「分配资源」和「被调度执行」两件事捆在一起，导致切换开销大、通信代价大、并发粒度粗，难以满足客户/服务器计算的要求。解决办法是把这两项功能分开：进程作为资源分配单位，线程作为调度执行的基本单位。线程是进程中的一条执行路径，有自己私用的运行栈和处理机执行环境，与同进程的其他线程共享内存、文件等资源；它同样有创建、就绪、运行、等待、终止等状态；线程之间也需要互斥与同步，除了继续使用信号量，还可以用互斥锁与条件变量（等待时释放锁、被唤醒后重新加锁）。

最后是 Linux 的实现实例，把本章的概念与真实接口对应起来：用 fork 一类的调用创建进程、用等待调用回收进程；信号量的使用围绕 semget（创建）、semctl（赋初值、删除）、semop（P、V 操作）三个系统调用展开；共享内存用 shmget 取得句柄、用 shmctl 释放；线程则由 pthread 库的 pthread_create 创建、pthread_exit 终止、pthread_join 等待回收。

本节小结

  • 本章的主线是「并发带来的问题 → 描述并发的手段 → 协调并发的机构 → 机构的具体应用」：顺序执行与并发执行的差别引出了进程，进程的状态与 PCB 描述它的动态行为，进程控制原语完成它的生老病死；
  • 并发进程之间的两种制约关系是互斥（争用临界资源）与同步（协作的先后次序），对应两类同步机构：锁（上锁/开锁原语）与信号灯（P、V 操作）；
  • 互斥的解法是一个初值为 1 的互斥信号灯；同步的解法是先画进程流图、再设初值为 0 的同步信号灯；共享缓冲区要一「满」一「空」两个信号灯；
  • 生产者—消费者问题把上面的一切合起来：sa（满，初值 0）、sb（空，初值 n）负责同步，mutex（初值 1）负责互斥，其中 P 操作的次序不可颠倒；
  • 线程把「资源分配」与「调度执行」分开，成为更细的并发单位，其互斥与同步可用信号量、互斥锁与条件变量实现；
  • Linux 用 semget/semctl/semop 管理信号量，用 shmget/shmctl 管理共享内存，用 pthread_create/exit/join 管理线程——概念与接口一一对应。
