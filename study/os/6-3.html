6.3 作业调度算法

作业调度算法要回答的是：磁盘后备队列里躺着好几个作业，按什么次序把它们挑进主存运行？同一批作业、同一台处理机，换一种调度算法，平均周转时间和平均带权周转时间就可能相差一大截——这正是评价调度算法好坏的基本尺子。本节的线索是：先给出这几个衡量指标的定义，再逐个讲解四种常用的作业调度算法——先来先服务、短作业优先、响应比高者优先和优先调度算法，并用同一批作业的数据把每种算法都算一遍、比一比。

1. 调度算法性能的衡量

衡量一个作业调度算法好不好，最常用的指标是作业的周转时间和带权周转时间，以及它们的平均值。这几个量都不是另做测量得来的，而是从作业进入系统时就记下来的时间信息里算出来的——6.2 节讲的作业控制块 JCB 里就已经存了「进入系统时间」和「估计执行时间」。

（1）周转时间

作业 i 的周转时间 ti，是它从进入系统到运行完成所经历的全部时间，也就是完成时刻减去进入时刻：ti = tci − tsi。其中 tsi 为作业 i 进入系统（即处于后备状态）的时刻，tci 为作业 i 的完成时刻。周转时间也叫响应时间，它包括了作业的等待时间加上执行时间：作业在后备队列里排队是等待，真正占用处理机运行是执行。

（2）平均周转时间

把 n 个作业的周转时间加起来再除以 n，就得到作业的平均周转时间 t。单个作业的周转时间只说明它自己等得久不久，平均周转时间才反映系统对一批作业的整体响应快慢，所以比较调度算法时看的是这个平均值。

（3）带权周转时间

只看周转时间还不够公平：周转时间的长短里混着作业本身大小的成分。同样是等上 1 个小时，一个原本就要执行 2.00 小时的作业只算慢了半拍，而一个只需执行 0.10 小时的作业，等待时间已经是自身长度的十倍。于是用作业的周转时间除以它自己的执行时间，消除作业大小的影响，得到带权周转时间 wi = ti / tri，其中 tri 为作业 i 的执行时间。由「周转时间 = 等待时间 + 执行时间」可知，wi 相当于「1 加上等待时间占执行时间的倍数」：wi = 1 说明作业一到就立刻投入运行、没有任何等待，等待越多这个倍数越大。

（4）平均带权周转时间

各个作业带权周转时间的平均值就是平均带权周转时间 w。它比平均周转时间更能暴露「短作业被长作业堵住」这类毛病：短作业的执行时间本身很小，多等一会儿，带权周转时间就会成倍上升，进而把平均值拉高。下面四种算法都用同一批作业（4 个作业，8.00 起陆续进入系统）来算，正好可以直接对比这两个平均值。

2. 先来先服务调度算法

先来先服务 FCFS（First Come First Served）调度算法按作业来到的先后次序进行调度：谁先进入系统，谁就先被选中运行；作业一旦投入运行，就一直运行到结束。它的特点是优先考虑等待时间较长的作业，而不管作业执行时间的长短。

这种算法容易实现——后备队列按到达时间排队，每次取队首作业即可，不需要额外的比较和计算。但它的系统效率较低，因为对短作业不利：短作业如果排在长作业后面，就得陪着长作业一起等，自己的周转时间被拉得很长，带权周转时间会很高。

平均周转时间 t=1.725　平均带权周转时间 w=6.875单位：小时

表中的数字都可以验算。作业 1 在 8.00 进入系统，当时只有它一个作业，于是 8.00 开始运行，执行 2.00 小时后在 10.00 完成：周转时间 = 10.00 − 8.00 = 2.00，带权周转时间 = 2.00 / 2.00 = 1。作业 2、3、4 分别在 8.50、9.00、9.50 进入系统，但处理机一直被作业 1 占着，只能等到 10.00 才轮到，此后按到达先后依次运行。作业 2 从 10.00 到 10.50，周转时间 = 10.50 − 8.50 = 2.00，带权周转时间 = 2.00 / 0.50 = 4；作业 3 从 10.50 到 10.60，周转时间 = 10.60 − 9.00 = 1.60，带权周转时间 = 1.60 / 0.10 = 16；作业 4 从 10.60 到 10.80，周转时间 = 10.80 − 9.50 = 1.30，带权周转时间 = 1.30 / 0.20 = 6.5。于是平均周转时间 t = (2.00 + 2.00 + 1.60 + 1.30) / 4 = 1.725，平均带权周转时间 w = (1 + 4 + 16 + 6.5) / 4 = 6.875。

特别值得看一眼作业 3：它只需要执行 0.10 小时，却从 9.00 一直等到 10.50，带权周转时间高达 16。这就是「对短作业不利」的具体样子，也是 FCFS 的平均带权周转时间被抬到 6.875 的原因。

3. 短作业优先调度算法

短作业优先 SJF（Shortest Job First）调度算法总是选取执行时间最短的作业执行：后备队列里谁的执行时间（由 JCB 中记录的估计执行时间给出）最小，就选谁先运行。它容易实现，而且系统效率较高——让短的作业先做完、尽快离开系统，平均周转时间和平均带权周转时间都会明显下降。

注：这一页课件把 SJF 的特点也写成「系统效率较低」，与 FCFS 那段几乎重复，应是笔误——本节三张表用的是同一批作业，SJF 的平均周转时间 1.55、平均带权周转时间 5.15 都低于 FCFS 的 1.725 和 6.875。这里按「系统效率较高」讲；复习时若遇到课件原话，以那三张表的数字为准。

缺点是它只照顾短作业的利益，不考虑长作业。如果系统不断接受新的作业，长作业可能长时间等待而不能运行：每来一个更短的作业，长作业就被往后推一位。

作业进入系统时间执行时间开始时间完成时间周转时间带权周转时间
18.002.008.0010.002.001
28.500.5010.3010.802.304.6
39.000.1010.0010.101.1011
49.500.2010.1010.300.804
平均周转时间 t=1.55　平均带权周转时间 w=5.15单位：小时

这里的调度次序是这样定下来的。8.00 时只有作业 1，它仍然独占处理机运行到 10.00。到 10.00 时作业 2（执行时间 0.50）、作业 3（0.10）、作业 4（0.20）都已在后备队列里，短作业优先算法挑执行时间最短的作业 3 先跑：作业 3 从 10.00 到 10.10，周转时间 = 10.10 − 9.00 = 1.10，带权周转时间 = 1.10 / 0.10 = 11。接下来在剩下的作业 2 和作业 4 之间再比一次，选执行时间较短的作业 4：从 10.10 到 10.30，周转时间 = 10.30 − 9.50 = 0.80，带权周转时间 = 0.80 / 0.20 = 4。最后才轮到作业 2：从 10.30 到 10.80，周转时间 = 10.80 − 8.50 = 2.30，带权周转时间 = 2.30 / 0.50 = 4.6。于是平均周转时间 t = (2.00 + 2.30 + 1.10 + 0.80) / 4 = 1.55，平均带权周转时间 w = (1 + 4.6 + 11 + 4) / 4 = 5.15。

与表 1 对照着看：短作业 3 的带权周转时间从 16 降到 11，短作业 4 从 6.5 降到 4，都是受益者；代价是执行时间较长一些的作业 2 被推到了最后，带权周转时间从 4 升到 4.6。两个平均值都下降了（t：1.725 → 1.55，w：6.875 → 5.15），说明对这批作业来说 SJF 确实比 FCFS 效率更高。

4. 响应比高者优先调度算法

前两种算法的毛病都在于「只认一头」：FCFS 只看等待时间，SJF 只看执行时间。响应比高者优先调度算法（Highest Response Ratio Next，HRRN）想把两头都照顾到，办法是给每个作业算一个响应比：响应比 = 响应时间 / 执行时间 = 1 + 等待时间 / 执行时间。它的做法是：在每一次要选择一个作业运行时，都实时动态计算所有作业的响应比，选择响应比高的作业运行。

从公式就能看出它的取舍。等待时间越长，响应比越高，先来的作业迟早会占优，这是照顾作业到来的先后；执行时间越短，响应比越高，短作业一进队列就能拿到较高的响应比，这是照顾短作业。而且等待时间在分子上会随时间不断增长，长作业等久了响应比也会升上去，不会像 SJF 那样被后来的短作业无限期插队。它的代价是实现性能较差：每选一次作业，都要把当前所有候选作业的响应比算一遍再比较。

作业进入系统时间执行时间开始时间完成时间周转时间带权周转时间
18.002.008.0010.002.001
28.500.5010.1010.602.104.2
39.000.1010.0010.101.1011
49.500.2010.6010.801.306.5
平均周转时间 t=1.625　平均带权周转时间 w=5.675单位：小时

响应比法的关键在第 2 步和第 3 步的选择，把当时的响应比算出来就一目了然。8.00 时只有作业 1，它运行到 10.00 完成。到 10.00，后备队列里有三个作业，各自的响应比为：作业 2 = 1 + (10.00 − 8.50) / 0.50 = 4；作业 3 = 1 + (10.00 − 9.00) / 0.10 = 11；作业 4 = 1 + (10.00 − 9.50) / 0.20 = 3.5。作业 3 的响应比最高，于是先运行，10.00 到 10.10 完成，周转时间 = 1.10、带权周转时间 = 11。到 10.10 再算一次：作业 2 = 1 + (10.10 − 8.50) / 0.50 = 4.2，作业 4 = 1 + (10.10 − 9.50) / 0.20 = 4.0，这一步作业 2 的响应比略高，所以选作业 2 运行（10.10 到 10.60），最后作业 4 从 10.60 运行到 10.80。

注意表中的带权周转时间正是在「被选中运行的那一刻」算出的响应比：作业一旦开始运行，它的等待时间就不再增加，周转时间 = 等待时间 + 执行时间，再除以执行时间就还原成响应比，作业 2 的 4.2、作业 4 的 6.5 都能这样对上。按表算平均值：平均周转时间 t = (2.00 + 2.10 + 1.10 + 1.30) / 4 = 1.625，平均带权周转时间 w = (1 + 4.2 + 11 + 6.5) / 4 = 5.675，都落在 FCFS 与 SJF 之间——它既照顾了作业到来的先后，又考虑了作业的执行时间长短，是前两种算法较好的折中。

5. 优先调度算法

优先调度算法（Priority Scheduling）不再局限于某一个标准，而是综合考虑有关因素——作业的缓急程度、作业大小、等待时间、资源使用等——并根据系统设计目标分析这些因素对调度性能的影响，然后自定义一种方法确定每个作业的优先级，调度时选择优先级高者先执行。换句话说，FCFS 和 SJF 都可以看成它的特例：前者把「优先级」取成到达时间的先后，后者取成执行时间的倒数。

优先级的确定方式有两种。作业的优先级可以在作业进入系统时确定，一经确定就不再改变，这叫静态优先级；也可以在每次需要选择作业时算出，随着作业的等待情况和系统状态而变化，这叫动态优先级。静态优先级实现简单、计算开销小，但作业在等待期间处境的变化体现不出来；动态优先级调度更灵活，代价是每次选择都要重新计算。这个思路在 6.5 节进程调度的优先数算法里会再次出现，只是作用的对象从作业换成了进程。

课件的例子给出了一个具体的设计方法。假设调度目标是优先考虑输出量较少、执行时间较短、等待时间较长的作业先运行，那么可以设计：

优先级 = 等待时间² − 执行时间 − 16 × 输出量，优先级高者先运行。

三个目标被直接写进了加减号和系数里：等待时间取平方，等待越久加分增长得越快，于是等待时间较长的作业占优；执行时间与输出量前面都是负号，取值越小优先级越高，于是执行时间较短、输出量较少的作业占优；系数 16 则体现输出量这一因素在调度目标中占多大分量。要优先照顾谁，就把它写进公式并给它合适的权重——这正是优先调度算法比前三种灵活的地方，而灵活性从哪来，取决于系统到底想优化什么。

本节小结

  • 衡量调度算法看两个量：周转时间 ti = tci − tsi（也叫响应时间，等于等待时间 + 执行时间）与带权周转时间 wi = ti / tri；比较算法时看它们的平均值 t 和 w。
  • 先来先服务 FCFS：按作业到达的先后次序调度，实现最简单，优先考虑等待时间长的作业而不管执行时间长短；对短作业不利，带权周转时间会很高（本例 t=1.725、w=6.875）。
  • 短作业优先 SJF：总是选取执行时间最短的作业，容易实现、系统效率较高（本例 t=1.55、w=5.15，三种算法里最低）；缺点是只照顾短作业，若系统不断接受新作业，长作业可能长时间等待而不能运行。
  • 响应比高者优先：每次选择时都实时动态计算所有作业的响应比（= 响应时间 / 执行时间 = 1 + 等待时间 / 执行时间），选高者运行；既照顾到来的先后又考虑执行时间长短，是前两种算法较好的折中（本例 t=1.625、w=5.675），代价是实现性能较差。
  • 优先调度算法：把缓急程度、作业大小、等待时间、资源使用等因素按系统设计目标折算成优先级，高者先执行；优先级在作业进入系统时确定的是静态优先级，每次选择时算出的是动态优先级。
  • 四种算法的分歧，说到底是怎么看待「等待时间」和「执行时间」：FCFS 只看前者，SJF 只看后者，响应比把两者相除求比值，优先调度算法则允许按设计目标自由加权——公式怎么设计，调度就偏向谁。
