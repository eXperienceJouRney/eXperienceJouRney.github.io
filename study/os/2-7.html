操作系统原理 · 第 2 章 结构与硬件支持

2.7 小结

这一节把第 2 章「结构与硬件支持」收个口。本章的中心问题只有一个：操作系统凭什么能在裸机上撑起一个多用户、多任务的运行环境？答案是它把自己做成了「操作系统虚拟机」，再借助处理机的态和中断这两项硬件支持来约束和保护自己。下面按「虚拟机 → 结构 → 态 → 中断」的顺序把要点过一遍。

1. 什么是操作系统虚拟机

硬件层（裸机）由 CPU、存储器和外部设备组成，它是所有软件运行的基本物质基础和环境。配置在裸机上的第一层软件就是操作系统；在裸机上配置了操作系统之后，就构成了操作系统虚拟机。

为什么要引入虚拟机的概念？有三条理由：

  • 多个用户程序要共享和竞争计算机的软、硬资源，而每个用户程序都希望自己是独自使用整个计算机系统，不会考虑其他用户进程的并行——用「虚拟」的办法分配资源，可以有效地实现资源共享；
  • 屏蔽不同硬件的差别，向上提供一致的用户操作接口；
  • 用户提出的要求是多方面的，所需功能十分丰富，很多复杂功能完全可以用软件来完成，从而扩充硬件的基本功能。

具体做法是：操作系统虚拟机用数据结构和函数的形式，用软件扩展硬件资源，更好地实现资源的并发与共享，方便用户使用。于是它就有了自己的一套指令系统，由两部分组成：裸机原有的硬件指令系统，以及操作系统虚拟机扩充的指令系统。扩充的这一部分又分两类：

  • 操作命令（又称命令接口）：键盘命令、作业控制语言（shell）、图形化用户界面 GUI；
  • 系统功能调用（又称程序接口）：系统函数和系统调用。

从程序的角度看，这个虚拟机是一条清晰的调用链：应用程序 → 函数调用 → 系统库 → 系统调用 → 操作系统内核 → 机器指令 → 硬件。第 3 章讲的用户接口，就是这条链上两层扩充指令的展开。

2. 操作系统的结构

操作系统的设计呈现出三个特征：复杂程度高、生成周期长、正确性难保证。这从代码量上看得最清楚：CTSS 约 32000 行；OS/360 达百万条指令、4000 个模块、耗费 5000 人年；Multics 达千万条指令；Windows 2000 有 3200 万行代码、2500 人参与；Linux 的代码量则呈指数增长。研究操作系统的组织结构，就是要弄清进程管理、处理机管理、存储管理、设备管理、文件系统这些功能模块之间如何组织、如何调用。

组织结构的发展大致经历四种类型：

（1）单体结构

操作系统是一组函数或过程的集合，这些过程之间可以相互调用而不受约束，实质上就是无结构的操作系统。优点是运行效率高；缺点是难以理解、难以维护、难以验证。AT&T System V 和 BSD UNIX 属于这一类。

（2）模块结构

操作系统由多个逻辑上独立的功能模块构成，各模块之间有良好定义的接口，模块内部隐藏实现细节，模块之间可以相互调用，因而有利于理解和维护。模块化追求的目标是「模块内部高聚合，模块之间低耦合」。

（3）层次结构

把操作系统划分为内核和若干功能模块，各层单向依赖，不构成循环。优点是系统结构清晰；整体问题局部化，系统的正确性可通过各层的正确性来保证；增加、修改或替换某一层不影响其他层，有利于维护和扩充。缺点是限制过于严格，过于追求形式反而会更复杂、效率低——它不现实，只是一种指导原则。

（4）可扩展内核结构（微内核）

把内核分为基础核心和其他核心功能两部分：基础核心只包括必需的最基本功能——处理器管理、低级存储器管理、中断处理、进程间通信；操作系统的其他功能则通过运行在核外的服务进程实现，采用客户/服务器方式，这些服务进程包括文件系统、设备驱动、网络协议栈、图形系统、各种虚拟资源管理等。它的优点是灵活性、易维护性和可扩充性（内核稳定，服务进程便于定制）；缺点是效率非常低——内核把用户请求传给服务器，服务器进程执行请求，内核再把结果返回用户程序，其间要付出消息发送拷贝、处理器状态切换、虚拟内存切换的代价。代表性系统有卡耐基梅隆大学研制的 Mach OS（1985 年启动，1994 年发布 Mach 3.0）、iOS、L4 与 seL4、Quantum Software Systems 公司的 QNX，以及 HarmonyOS Next 鸿蒙微内核。

再看几个实例：UNIX 分核心层（处理机管理、存储管理、设备管理、文件系统）和实用层（编辑程序、调试程序、系统状态监控、文件管理等实用程序，以及 SCCS 等存储管理软件工具）；Linux 的核心结构是模块化（大模块、小模块）、局部的层次化，并带有微内核的趋势；Windows 的设计目标是可扩充性、可移植性、可靠性与坚固性、兼容性和高性能，它采用基于对象技术的 C/S 结构，在纯微内核结构的基础上做了扩展，融合了层次式结构和微内核结构的特点——对性能影响很大的组件放在内核下运行，其他功能在内核外实现，因而模块化程度高、灵活性大、便于维护、系统性能好；Android 自下而上依次是 Linux 内核（隐藏硬件、网络细节，为上层提供统一的接口）、原生 C++ 实现的核心与扩展类库（要被上层调用须经 JNI 导出接口函数）、包含 SDK 类库的框架层，以及最上面的应用层。

3. 区分处理机的态的目的

系统中存在两类职责完全不同的程序：管理程序负责管理系统资源、控制程序运行；用户程序使用资源、提出申请、被控制。既然用户程序是被管理者，它就有可能因为错误或恶意而破坏管理系统，所以必须把两者的权限分开。区分处理机状态的目的，一句话就是保护操作系统。

处理机的态又称处理机的特权级，是中央处理机的工作状态。当前处理机正在执行哪类程序，决定处理机处于哪种态。为此至少需要区分两种状态，硬件上通常只需在一个特定寄存器中设置 1 bit 的系统状态位。

4. 管态与用户态的区别

  • 管态（Supervisor mode，又称系统态）：操作系统的管理程序执行时机器所处的状态。在此状态下，处理机可使用全部指令（包括一组特权指令），使用全部系统资源（包括整个存储区域）。
  • 用户态（User mode，又称目态）：用户程序执行时机器所处的状态。在此状态下禁止使用特权指令，不能直接取用资源与改变机器状态，并且只允许用户程序访问自己的存储区域。

所谓特权指令，指的是涉及外部设备的输入/输出指令与允许/禁止中断的指令、修改特殊寄存器的指令、改变机器状态的指令。如果用户程序执行时超出了权限，都将产生中断（程序性中断或保护性中断），系统由用户态转为管态，操作系统得到 CPU 控制权，来处理这一非法事件。

状态切换的路径也是明确的：用户态转到核态的情况有四种——用户程序要求操作系统提供服务而执行系统功能调用（中断或系统调用指令）、运行中偶然发生一次硬件中断、用户程序产生错误（程序性中断）、用户程序企图执行特权指令；核态转到用户态则靠中断返回，而这条指令本身也是特权指令。

5. 中断的定义与类型

中断是指某个事件（例如电源掉电、计算异常或 I/O 传输结束等）发生时，系统中止现行程序的运行、引出处理事件程序对该事件进行处理，处理完毕后返回断点继续执行的过程。整个事件可以画成「正在执行的程序 → 中断信号 → 中断进入 → 中断处理程序 → 中断返回 → 继续执行」这样一条链路。

中断可以按三个角度分类：

  • 按功能：① 输入输出中断（I/O 传输结束或出错）；② 外中断（时钟中断、操作员控制台中断、多核通信等）；③ 机器故障中断（电源故障、主存取指令错等）；④ 程序性中断（计算异常、用户态下使用核态指令、非法操作）；⑤ 访管中断（对操作系统提出某种需求时发出的中断，即系统调用中断）。
  • 按方式：① 强迫性中断——不是正在运行的程序所期待的中断，用户程序不可控，包括输入输出中断、外中断、机器故障中断、程序性中断；② 自愿中断——运行程序所期待的事件，即访管中断。
  • 按来源：① 中断，由处理机外部事件引起；② 俘获，由处理机内部事件引起，又叫异常。

6. 中断响应：定义、实质与所需的硬件支持

中断响应是当中央处理机发现已有中断请求时，中止现行程序执行，并自动进入中断处理程序的过程。它的实质就是由硬件完成两件事：保留程序断点及处理机的有关信息，然后自动转入相应的中断处理程序执行。

要做到这一点，硬件必须提供四样支持：指令计数器（记住断点）、处理机状态寄存器（记住当时的机器状态）、系统堆栈（保存断点现场）、中断向量表（找到处理程序入口）。

与断点现场直接相关的是程序状态字。它反映指令执行时机器所处的现行状态，因为非常重要，所以放在特定寄存器中（PC 指令计数器、PS 处理器状态寄存器）。其内容包括指令地址、指令执行情况、处理机状态、应屏蔽的中断等。例如 x86 PC 的程序状态字是 CS:IP（指令地址）加 FLAGS（标志寄存器），ARM 处理器则是 R15（指令计数器）加 CPSR（处理器状态寄存器）。

另一个关键设施是中断向量表。当中断发生时，由中断源自己引导处理机进入中断服务程序，这种中断过程称为向量中断；每个中断类型都有自己的中断向量，其中包含中断服务程序的入口地址；主存中用于存放这些中断向量的存储单元组成的表，就是中断向量表。在 x86 PC 中，全部 256 个中断的中断向量放在一张表上，它占用内存区最低的 1 KB（地址 00000H～003FFH）。

7. 软件中断处理过程

中断处理是硬件和软件结合完成的，所有计算机系统都采用这种方式。当硬件完成了中断进入过程后，控制权交给相应的中断处理程序，软件要接着做四步：

  • （1）保护现场。现场是指中断返回时能确保程序继续运行的有关信息，除了 PC 和 PS，几乎包括其他所有寄存器。中断发生时，必须立即把现场信息保存在主存中，这项工作称为保护现场。
  • （2）进入相应的中断服务例程执行中断处理，按类型可分为硬件故障中断的处理、程序性中断的处理、外部中断事件的处理、外部设备中断的处理。
  • （3）恢复现场。程序重新运行之前，把保留的该程序现场信息从主存送至相应的指令计数器、通用寄存器或一些特殊的寄存器。
  • （4）中断返回，回到被中断程序的断点继续执行。

Linux 对中断的支持是这一套机制的现代实例：它至少支持两个特权级别，实际使用特权级 0（核态／内核模式）和特权级 3（用户态／用户模式）；中断处理分为上半部和下半部——上半部（top half）是中断响应后必须立即处理、有严格时间限制的关键而紧迫的工作（如与硬件设备应答或使硬件复位），它在屏蔽所有中断的情况下进行，不可被打断；下半部（bottom half）是可以稍后完成的工作，在开中断的情况下执行，可以被打断。原则上应把更多处理工作向后推迟到下半部。

最后要记住贯穿本章的结论：中断是操作系统的基础，是实现并发的根本措施；它也是程序得以运行的直接或间接的「向导」，是程序被激活的驱动源。只有透彻了解中断的机理，才能深刻体会操作系统的内在结构——这一点在第 4 章讲进程与并发时会反复用到。

本节小结

  • 裸机（CPU、存储器、外部设备）＋操作系统＝操作系统虚拟机；它用数据结构和函数的形式以软件扩展硬件资源，扩充的指令系统分命令接口（键盘命令、shell、GUI）和程序接口（系统函数、系统调用）两类。
  • 操作系统的组织结构从单体结构、模块结构、层次结构发展到可扩展内核结构（微内核）：单体效率高但难维护，模块化追求模块内高聚合、模块间低耦合，层次结构清晰但限制过严，微内核灵活可扩充但效率低；UNIX、Linux、Windows、Android、鸿蒙各取其法。
  • 处理机的态就是特权级，区分它的目的是保护操作系统；管态可用全部指令和全部资源，用户态禁止特权指令、只能访问自己的存储区域，两态靠 1 bit 状态位和中断相互切换。
  • 中断是事件发生时中止现行程序、引出处理程序处理、处理完返回断点的过程；按功能分外中断、I/O 中断、机器故障中断、程序性中断、访管中断，按方式分强迫性中断与自愿中断，按来源分中断与俘获（异常）。
  • 中断响应的实质是硬件保留断点并自动转入中断处理程序，靠指令计数器、处理机状态寄存器、系统堆栈和中断向量表支持；软件随后依次保护现场、执行中断服务例程、恢复现场、中断返回。
  • 下一章转入用户接口：用户工作环境如何建立、应用程序如何处理、命令接口与系统功能调用各是什么——那是本章这两类扩充指令的正式展开。
