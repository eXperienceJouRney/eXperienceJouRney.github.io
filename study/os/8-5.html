操作系统原理 · 第 8 章 设备管理

8.5 小结

这一章回答的是同一个问题的四个侧面：怎样让形态各异的外部设备，变成上层可以放心使用的资源。8.1 节先把外设的差异摆清楚，定下「提高利用率、方便使用」两个目标与设备独立性、设备一致性两条抽象原则；8.2 节的缓冲用来抹平速度差；8.3 节的分配技术决定设备分给谁、用多久；8.4 节的控制方式与 I/O 子系统负责把数据真正搬起来。下面按课件的收尾线索，先把四节串成一条线，再重点回顾设备分配技术与 I/O 控制中的同步关系。

1. 一条主线：从参差不齐的外设到统一的资源

设备管理的困难来自硬件本身：外设在速度、传输单位、容许的操作、出错条件、传输方式等方面差异极大，所以它被称为操作系统中最庞杂、最琐碎的部分。对策有两步：

  • 抽象——设备一致性要求用相同的方法操作所有设备、用相同的方法操作一类设备，同一类设备共用一个设备驱动程序；设备独立性则让用户程序只用逻辑设备名，由系统把它换成物理设备名。
  • 记录——每台设备的状态与归属都记在设备控制块 DCB 里：设备名、设备属性、指向命令转换表的指针、在 I/O 总线上的设备地址、设备状态、当前用户进程指针、I/O 请求进程队列指针。命令转换表存放设备驱动和控制程序的入口地址，不支持的操作用 -1 或 NULL 占位。

有了这两步，设备管理的三项功能才有落脚点：动态地跟踪状态、按静态（应用程序级）或动态（进程级）方式分配与回收设备、用 I/O 指令实施设备控制。

2. 缓冲技术：抹平速度差

缓冲是两种不同速度的设备之间传输信息时平滑传输过程的手段，硬件形态是容量小、速度快的缓冲器，软件形态是 I/O 期间临时存放 I/O 数据的一块主存区域。它的作用集中在四点：平滑生产者与消费者的速度差、协调传输数据大小不一致的设备、保证系统调用写入数据的拷贝语义、提高并行程度。

常用的缓冲技术有三种，正好对应并行程度的三级台阶：

  • 双缓冲：为输入或输出分配 buf1、buf2，一个在装、另一个在取，设备与 CPU 得以并行；两个缓冲可分别用于输入、输出，也可同时兼顾；
  • 环形缓冲：把若干缓冲区链成环，用 start、in、out 三个指针管理，in 指向第一个空缓冲区、out 指向第一个满缓冲区；生产者—消费者用信号量 S1（空缓冲区数）、S2（满缓冲区数）同步，多个生产者/消费者时还需互斥；
  • 缓冲池：UNIX 的磁盘缓冲，思路是预先缓存与延迟发送。一个缓冲区＝缓冲数组＋缓冲首部（dev、blkno、flag：BUSY、AVE、DELWR、WRITE、READ、WAIT），它同时挂在空闲缓冲区队列（av 链）与设备缓冲区队列（b 链）上；取空闲缓冲区取队头、释放时挂队尾，因而得到精确的 LRU 淘汰。getblk 取用缓冲区，brelse 释放并唤醒等待者，代价是延迟写带来的崩溃丢失风险。

3. 设备分配：把有限的设备分好

课件的收尾把常用的设备分配技术概括为三组「设备—技术」：

常用的设备分配技术（据原课件第 84 张本章小结整理）
设备分配技术要点
独享设备独享分配（静态分配）打印机、输入磁带机一类只允许一个程序独占使用的设备，费时或需人工干预、多人同时使用会混乱；在作业执行前分配，作业结束撤离时收回，属于应用程序级分配
共享设备共享分配（动态分配）磁盘一类可由多个作业、进程共同使用的设备，可直接或随机访问、存取快；进程提出申请时由设备模块分配，使用完毕立即归还，属于进程级分配
虚拟设备虚拟技术用便于共享的、快速的存储设备替代不适合共享的、慢速的字符设备，采用预先收存与延迟发送，把慢速独占设备转化为快速可共享设备；代替独占设备的那部分辅存空间（含有关控制表格）就是虚拟设备
SPOOLing 系统假脱机虚拟设备最完整的实现：利用通道和中断技术，由预输入程序、缓输出程序、井管理程序与预输入表、缓输出表构成软件系统，提供输入收存与输出发送功能，使外部设备可以并行操作

多个请求竞争同一台设备时，还要有分配算法：先请求先服务与按优先级高低——与第 5 章 5.2 节资源分配机制和策略中的 FCFS、优先调度策略同源。SPOOLing 系统的工作建立在四项基础之上：大容量的辅存空间（输入井、输出井）、通道装置与中断系统、预输入表/缓输出表等数据结构，以及相应的软件程序；它带来的好处是提供虚拟设备、外围设备同时联机操作、加快作业处理速度。

4. I/O 控制：把数据真正搬起来

课件的收尾把I/O 控制归结为两件事：I/O 控制的主要功能，以及请求 I/O 的各部分之间的同步关系。

（1）I/O 控制的主要功能

操作系统用抽象、封装、分层、模块化的方法组织输入/输出子系统：把使用特性相似的设备归为一类，用设备驱动程序封装硬件差异。I/O 子系统的功能有三项——解释用户的 I/O 系统调用、设备驱动、中断处理；完整操作一个设备的软件模块也相应地分为这三部分。控制设备 I/O 工作的核心模块就是设备驱动程序，调用它有两条路：为每一类设备设置一个设备处理进程（有请求则唤醒、无请求则睡眠），或者把设备当文件一样对待，用文件系统的系统调用经索引节点进入驱动程序。

（2）请求 I/O 的各部分及其同步关系

一次 I/O 由四个角色接力完成，它们之间的同步关系可以概括成三次「唤醒」：

  • 用户进程发出 doio(ldev, mode, amount, addr)，然后等待 I/O 完成；
  • I/O 系统调用过程把逻辑设备名转换为物理设备名，依据 DCB 的命令转换表检查操作合法性，构造 I/O 请求块 IORB 并挂入设备请求队列，然后唤醒因等待 I/O 请求块而睡眠的设备处理进程；
  • 设备处理进程取出 IORB、启动 I/O 操作，随后睡眠等待 I/O 完成；
  • 中断处理程序在设备 I/O 完成引发中断时执行中断服务，并唤醒设备处理进程；设备处理进程完成数据传送与出错处理后，再唤醒等待 I/O 的用户进程。

这四者之间有两条关系要分清：一条是控制关系，请求沿「用户进程 → I/O 系统调用过程 → 设备处理进程 → I/O 设备」传递；另一条是同步关系，即设备处理进程与中断处理程序之间靠中断信号与唤醒操作相互配合。正是这套「唤醒—睡眠—再唤醒」的机制，让 CPU 在一次 I/O 期间始终没有空等。

本节小结

  • 外设＝除 CPU 和主存以外的设备和装置，分存储设备（块设备）、输入/输出设备（字符设备）与通信设备；设备管理的目标是提高设备利用率和方便用户使用，手段是缓冲区、通道、中断等技术加上设备独立性与设备一致性；
  • 描述设备的数据结构是设备控制块 DCB，其中命令转换表指明该设备的驱动程序入口；这是设备独立性与设备控制共同的落点；
  • 缓冲的三种常用技术是双缓冲、环形缓冲和缓冲池；缓冲池（UNIX）以预先缓存、延迟发送为思路，用两条队列和 LRU 淘汰提高有限缓冲的利用率；
  • 设备分配技术随设备特性分三类：独享设备用独享分配（静态）、共享设备用共享分配（动态）、慢速独占设备用虚拟技术改造成虚拟设备；SPOOLing 系统是虚拟设备的经典实现，靠输入井、输出井与预输入/缓输出程序让外围设备同时联机操作；
  • I/O 控制沿「循环测试 → I/O 中断 → 通道 → DMA」演进，CPU 的介入越来越少；I/O 子系统的功能是解释 I/O 系统调用、设备驱动与中断处理；
  • 一次完整的 I/O 就是用户进程、I/O 系统调用过程、设备处理进程与中断处理程序四者按控制关系传递请求、按同步关系互相唤醒的过程。
